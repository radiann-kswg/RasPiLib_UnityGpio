# 要件定義

2026-09-26 のセッションで決めた内容。「確定」は利用者と合意した事項、
「仮」は合意の範囲内でエージェントが置いた既定値で、実装時に変えてよい。

## 1. 目的

Raspberry Pi 上で動く Unity ゲームから GPIO を使い、フルカラー LED・サーボ・I2C センサーなどで
**独自の拡張ゲームパーツ**を作れるようにする。最初の搭載先は
[RasPiOS_UnityConsole](https://github.com/radiann-kswg/RasPiOS_UnityConsole) だが、
他の Raspberry Pi 用 OS でも使えるように作る。

## 2. 前提と制約

| 項目 | 内容 |
| --- | --- |
| Unity | 6.3 LTS（6000.3 系）。Linux x86_64 プレイヤー。Mono / IL2CPP の両方 |
| 対象ボード（確定） | Raspberry Pi 4B と Raspberry Pi 5。v1 から両方 |
| OS | Raspberry Pi OS（Debian trixie、arm64）。libgpiod v2 が使えること |
| 実行形態 | ゲームは box64 上の x86_64 プロセスでもよい → ゲームは arm64 のネイティブライブラリを読めない |

## 3. 確定した設計判断

| # | 項目 | 決定 |
| --- | --- | --- |
| D1 | 方式 | **常駐デーモン方式**。arm64 ネイティブの `unitygpiod` が GPIO を操作し、ゲームは純 C# の SDK からソケットで命令を送る |
| D2 | 対象ボード | Pi 4B と Pi 5 を v1 から両対応。違い（gpiochip の見つけ方・PWM の設定）はデーモンが吸収する |
| D3 | v1 の機能 | デジタル入出力（エッジイベント付き）・ハードウェア PWM 2ch・I2C の生読み書き・RGB LED の 4 つ |
| D4 | フルカラー LED | v1 は普通の RGB LED。3 ピン指定で、通常ピンはオン/オフ（8 色）、ハードウェア PWM ピンは明るさ可変（最大 2ch）。`activeLow` でアノードコモン/カソードコモンを切り替える。WS2812B は実物が手元に無いので v2 以降の拡張ツールへ |
| D5 | サーボ | Pi 本体のハードウェア PWM 2ch（GPIO12 / GPIO13）だけ。パルス幅の補正値を持つ。PCA9685 は v2 以降の拡張ツール |
| D6 | リポジトリとライセンス | デーモン・プロトコル・Unity SDK を **1 つの MIT リポジトリ `RasPiLib_UnityGpio`** に置く。OS 側はこれをサブモジュールで取り込む。UPM は Git URL の `?path=` 指定 |
| D7 | ピンの指定 | **BCM 番号で自由に指定**。ただし予約ピンと、有効なバス（I2C・PWM）が使うピンは拒否する。パーツ製作者向けに推奨ピン配置表を載せる（[architecture.md §6](architecture.md#6-ピン配置)） |
| D8 | I2C・PWM の有効化 | **設定で有効/無効を切り替え、再起動で反映**（Raspberry Pi 公式 OS の raspi-config と同じ流れ）。デーモンは起動時にカーネルの実状態を見て、使えるバスとピンを決める |
| D9 | 終了時 | ソケットが切れたら、その接続が使っていた出力をすべて安全な状態に戻す（デジタル出力は入力に戻す・PWM 停止・LED 消灯）。**SIGKILL でも働くこと（必須）** |
| D10 | 一時停止中 | v1 は**そのまま保持**。v2 以降でピンごとの `safeOnPause` 指定を追加する |
| D11 | 同時接続 | **1 接続だけ**。2 つ目は拒否する |
| D12 | Editor 開発 | v1 で**模擬モード**と**遠隔モード**の両方。遠隔モードの TCP は既定で無効・待受アドレスを設定で指定・共有トークンで認証 |
| D13 | C# API | 出力と PWM の書き込みは送るだけ（ブロックしない）。入力はデーモンから送られた変化を保持し、プロパティで即時に読める＋C# の event。I2C は `Awaitable<byte[]>` |
| D14 | 35 番ピン（GPIO19） | ホームボタン基板などで塞がる場合は基板を改版せず、HAT や 2x20 のブレークアウト用パーツ（垂直水平両用ピンヘッダ等）での引き出しを勧める |

## 4. 機能要件（v1）

### 4.1 デジタル入出力
- 出力: 初期値を指定して確保、値の書き込み。
- 入力: バイアス（`PullUp` / `PullDown` / `None`）、エッジ（`Rising` / `Falling` / `Both` / `None`）、
  デバウンス時間（ms）を指定して確保。値はプロパティで読め、変化は event で届く。
- event はゲームのメインスレッド（PlayerLoop の Update 前）で発火する。ゲームコードから Unity API を直接呼べること。

### 4.2 ハードウェア PWM
- GPIO12 / GPIO13 の 2ch。周波数（Hz）とデューティ比（0〜1）を指定する。
- 2 つのチャンネルは別々の周波数にできること（サーボ 50Hz と LED 1kHz の同時使用）。実機で要確認。
- サーボ用ヘルパー: 角度 → パルス幅に変換する。`minPulseUs` / `maxPulseUs` / `maxAngle` を補正値として持つ
  （既定は 500 / 2500 µs・180°。サーボの個体差を合わせるため）。

### 4.3 I2C
- I2C1（GPIO2 = SDA、GPIO3 = SCL）。アドレスを指定し、「書いて、続けて読む」を 1 回の往復で行う
  （リピーテッドスタート。センサーのレジスタ読み出しに必要）。書くだけ・読むだけも可。
- 戻り値は `Awaitable<byte[]>`。失敗（NACK・タイムアウト・無効）は例外で返す。

### 4.4 RGB LED
- `R` `G` `B` の 3 ピン、`activeLow` を指定する。色は `UnityEngine.Color`。
- ハードウェア PWM ピンに当たったチャンネルは明るさ可変、それ以外は 0.5 を閾値にオン/オフ。

### 4.5 可用性とエラー
- GPIO が無い環境（デーモン未導入・Windows のプレイヤー等）でも**ゲームは起動できる**こと。
  `Gpio.IsAvailable` で確認でき、使えない場合の操作は例外ではなく無視＋警告ログ（仮）。
- 送るだけの操作で起きたエラーはデーモンから非同期に届き、`Gpio.Error` event と `Debug.LogError` で知らせる。
- デーモンの再起動などで切れたら `Gpio.Disconnected` を発火する。v1 は自動再接続しない。

### 4.6 安全
- 予約ピン（OS が指定。UnityConsole ではホームボタンの GPIO21）は確保できない。
- 終了時の後始末は D9 のとおり。出力ピンは、解放する前に入力へ設定し直す
  （libgpiod は解放しただけでは最後の出力値が残るため）。
- 遠隔モードの TCP は既定で無効。有効にするときはトークン必須（トークン無しでは TCP を開かない）。

### 4.7 Editor 開発
- **模擬モード**: Editor の中だけでピンの状態を持つ。入力の値をスクリプトやインスペクタから変えられる。
  I2C は応答を差し込めるようにする（最小限。デバイスのエミュレーションは作らない）。
- **遠隔モード**: 実機のデーモンへ TCP で接続する。接続先とトークンは Editor のプロジェクト設定で指定し、
  ビルドには含めない。
- 既定は模擬モード。プレイヤー（Linux）では常に Unix ソケットで接続する。

## 5. 非機能要件

| 項目 | 目標 |
| --- | --- |
| 応答 | 出力の書き込みからピンが変わるまで、Unix ソケットで数 ms 以内を目安（60fps の 1 フレーム未満） |
| 依存 | デーモンは Python 3 標準ライブラリ＋`python3-libgpiod` のみ（仮）。SDK は Unity 標準のみ |
| 権限 | デーモンは root で動かさない（gpio・i2c グループ権限で動かす）。ソケットは `gpio` グループのみ読み書き可 |
| 検証 | デーモンのピン予約・後始末のロジックに 1 本の自己テスト。実機の結合試験は Pi 4B と Pi 5 の両方で行う |

## 6. ロードマップ

| 版 | 内容 |
| --- | --- |
| v1 | 本書 §4 のとおり |
| v2 以降（本体） | ① SPI（生のバイト読み書き）→ ② UART → ③ 1-Wire の順。一時停止中のピンごとの `safeOnPause` |
| v2 以降（拡張ツール） | SPI 対応と並行して開発・提供。**ゲーム開発者が必要なものだけ選んで導入する**別パッケージとし、個別に動作を保証する。候補: BME280 などの代表的センサードライバ、WS2812B（SPI の MOSI で波形を作る方式）、PCA9685（サーボ 16ch。周波数の補正値付き）、ソフトウェア PWM（非推奨扱い）、Input System 連携（GPIO のボタンを入力デバイスとして見せる） |

拡張ツールの置き場所（同じリポジトリ内の別パッケージにするか等）は v2 の設計時に決める。

## 7. 実装時に実機で確かめること

- Pi 5 の PWM overlay の指定方法と pwmchip の見つけ方（Pi 4B は `dtoverlay=pwm-2chan,pin=12,func=4,pin2=13,func2=4`）。
- PWM の 2 チャンネルを別周波数で同時に使えるか（Pi 4B / Pi 5）。
- box64 上の Unity（Mono / IL2CPP）から Unix ドメインソケットに接続できるか。
  できない場合はループバックの TCP（127.0.0.1、トークン不要）に切り替える。
- systemd の `DynamicUser` と追加グループでソケットのグループを `gpio` にできるか。
